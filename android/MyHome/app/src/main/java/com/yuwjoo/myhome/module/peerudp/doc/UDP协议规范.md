# UDP 协议规范

## 1. 帧结构

```
┌──────────┬──────────┬────────────┬───────────┬──────────┬───────────┬──────────┐
│ Byte 0-1 │ Byte 2   │ Byte 3-4   │ Byte 5    │ Byte 6-7 │ Byte 8-9  │ Byte 10+ │
│  Magic   │   Type   │  SeqNum    │  Flags    │  PayLen  │  CRC16    │ Payload  │
│  2 bytes │  1 byte  │  2 bytes   │  1 byte   │  2 bytes │  2 bytes  │ N bytes  │
└──────────┴──────────┴────────────┴───────────┴──────────┴───────────┴──────────┘
                         ◄────────────── 定长帧头 10 字节 ─────────────────►
```

帧头固定 **10 字节**，完整帧长 = 10 + Payload Len。

| 偏移 | 字节 | 字段 | 说明 |
|:---:|:---:|------|------|
| 0 | 2 | **Magic** | 协议魔数，固定 `0x59 0x48`（ASCII `YH`） |
| 2 | 1 | **Type** | 消息类型，见 [消息类型](#2-消息类型) |
| 3 | 2 | **SeqNum** | 消息序号（uint16 大端序）；无序消息固定为 `0x0000` |
| 5 | 1 | **Flags** | 标志位，见 [标志位](#3-标志位) |
| 6 | 2 | **Payload Len** | 负载字节数（uint16 大端序），空负载为 `0x0000` |
| 8 | 2 | **CRC16** | 校验值（uint16 大端序），范围 = 帧头前 6 字节 + 全部 Payload |
| 10 | N | **Payload** | 负载数据，通常为 UTF-8 JSON |

## 2. 消息类型

| 分类 | Type | 名称 | 说明 |
|:---:|:---:|------|------|
| **系统** | `0x01` | Heartbeat | 设备在线宣告，周期性广播，无序 |
| | `0x02` | Offline | 设备主动离网通知，无序 |
| | `0x03` | Call | 向新发现设备发起呼叫，单播，无序，携带设备信息 |
| | `0x04` | Answer | 回应 Call，单播，无序，携带设备信息 |
| | `0x05` | Ack | 消息确认应答，单播，无序，负载见 [Ack 负载结构](#4-ack-负载结构) |
| | `0x06-0x0F` | 保留 | — |
| **业务** | `0x10` | Json | JSON 消息，有序/无序按需 |
| | `0x11` | Raw | 原始消息，负载为自定义二进制 |
| | `0x12-0xEF` | 保留 | — |
| | `0xF0-0xFF` | 保留 | — |

## 3. 标志位

| Bit | 名称 | 说明 |
|:---:|------|------|
| 0 | **Ordered** | `0` 无序（立即发送、并行处理、不保证送达、可能重复）；`1` 有序（逐条发送、等待确认、不重复不丢包），隐含需回复 Ack |
| 1-7 | 保留 | 必须为 0 |

## 4. Ack 负载结构

Ack 的 Payload 为 2 字节定长二进制：

| 字段 | 字节 | 说明 |
|------|:---:|------|
| **AckSeq** | 0-1 | 被确认的消息序号（收到的 SeqNum，uint16 大端序） |
