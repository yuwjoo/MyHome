# UDP 协议规范

## 1. 帧结构

```
┌──────────┬──────────┬──────────┬──────────┬──────────┬───────────┬────────────┬──────────┐
│ Byte 0-1 │ Byte 2   │ Byte 3   │ Byte 4-5 │ Byte 6   │ Byte 7-8  │ Byte 9-10  │ Byte 11+ │
│  Magic   │ Version  │   Type   │  SeqNum  │  Flags   │  PayLen   │  CRC16     │ Payload  │
│  2 bytes │  1 byte  │  1 byte  │ 2 bytes  │  1 byte  │  2 bytes  │  2 bytes   │ N bytes  │
└──────────┴──────────┴──────────┴──────────┴──────────┴───────────┴────────────┴──────────┘
                         ◄────────────── 定长帧头 11 字节 ──────────────────►
```

| 偏移 | 字节 | 字段 | 说明 |
|:---:|:---:|------|------|
| 0 | 2 | **Magic** | 协议魔数，固定 `0x59 0x48`（ASCII `YH`） |
| 2 | 1 | **Version** | 协议版本，当前 `0x01` |
| 3 | 1 | **Type** | 消息类型，见 [§2](#2-消息类型) |
| 4 | 2 | **SeqNum** | 消息序号（uint16 大端序），见 [§3](#3-消息序号-seqnum) |
| 6 | 1 | **Flags** | 标志位，见 [§4](#4-标志位) |
| 7 | 2 | **Payload Len** | 负载字节数（uint16 大端序），空负载为 `0x0000` |
| 9 | 2 | **CRC16** | 校验值（uint16 大端序），见 [§5](#5-crc16-校验) |
| 11 | N | **Payload** | 负载数据，UTF-8 JSON |

帧头固定 **11 字节**，完整帧长 = 11 + Payload Len。

---

## 2. 消息类型

| 分类 | Type | 名称 | 说明 |
|:---:|:---:|------|------|
| **系统** | `0x01` | Heartbeat | 设备在线宣告，周期性广播 |
| | `0x02` | Offline | 设备主动离网通知 |
| | `0x03` | Call | 向新发现设备发起呼叫，请求其设备信息 |
| | `0x04` | Answer | 回应 Call，返回自身设备信息 |
| | `0x05` | Ack | 消息确认应答，见 [§3.3](#33-ack-消息格式) |
| | `0x06-0x0F` | 保留 | — |
| **业务** | `0x10` | Json | JSON 消息，见 [§6.2](#62-json-消息) |
| | `0x11` | Raw | 原始消息，负载为自定义二进制 |
| | `0x12-0xEF` | 保留 | — |
| | `0xF0-0xFF` | 保留 | — |

## 3. 消息序号 SeqNum

### 3.1 含义

SeqNum 为 uint16 大端序序号，由发送方自增管理。是否校验重复和排序由 Flags 中 **Ordered** 标志位控制，见 [§4](#4-标志位)。

### 3.2 有序消息处理规则

每个设备为每个通信对端（以 IP 标识）维护一个 `当前序号`（初始值 = 1）。

收到的 SeqNum 与当前序号比较：

| 条件 | 行为 |
|------|------|
| SeqNum **<** 当前序号 | 已消费过的重复/过期消息，**丢弃**，若 AckRequired 则回复 Ack |
| SeqNum **=** 当前序号 | 期望的下一条消息，**消费**，当前序号 +1，若 AckRequired 则回复 Ack |
| SeqNum **>** 当前序号 | 未来消息（中间有丢包），**丢弃**，若 AckRequired 则回复 Ack |

### 3.3 Ack 消息格式

当 Flags 中 AckRequired 置位，接收方必须回复 Ack。Ack 的 Payload 为 4 字节定长二进制：

```
┌───────────┬───────────┐
│ Byte 0-1  │ Byte 2-3  │
│  AckSeq   │ CurrentSeq│
│  uint16   │  uint16   │
└───────────┴───────────┘
```

| 字段 | 字节 | 说明 |
|------|:---:|------|
| **AckSeq** | 0-1 | 被确认的消息序号（收到的 SeqNum） |
| **CurrentSeq** | 2-3 | 接收方记录的最新当前序号 |

> 发送方通过 CurrentSeq 获知对端消费进度，识别哪些序号已完成或需要重传。

### 3.4 使用场景对照

| 消息 | 发送方式 | Ordered | AckRequired | 说明 |
|------|:---:|:---:|:---:|------|
| Heartbeat | 广播 | 0 | 0 | 无序，收到即处理 |
| Offline | 广播 | 0 | 0 | 无序，收到即处理 |
| Call | 单播 | 0 | 0 | 无序，响应用 Answer |
| Answer | 单播 | 0 | 0 | 无序，收到即记录 |
| Ack | 单播 | 0 | 0 | 无序，收到即处理 |
| Json | 单播 | 按需 | 按需 | 可按需开启有序+确认 |
| Raw | 单播 | 按需 | 按需 | 二进制数据，可按需开启有序+确认 |

## 4. 标志位

| Bit | 名称 | 说明 |
|:---:|------|------|
| 0 | **AckRequired** | `0` 无需回复 Ack；`1` 接收方必须回复 Ack |
| 1 | **Ordered** | `0` 无序，可能重复接收；`1` 有序，不会重复接收 |
| 2-7 | 保留 | 必须为 0 |

---

## 5. CRC16 校验

- **算法**：CRC-16/CCITT-FALSE
- **多项式**：`0x1021`
- **初始值**：`0xFFFF`
- **校验范围**：帧头第 0~8 字节（Magic ~ Payload Len）+ 全部 Payload 字节

```
CRC16( Magic[2] + Version[1] + Type[1] + SeqNum[2] + Flags[1] + PayLen[2] + Payload[N] )
```

处理流程：

```
发送方：计算 CRC16 → 填入 → 发送
接收方：提取 CRC16 → 对相同范围重算 → 比对
        一致 → 继续处理
        不一致 → 丢弃
```

## 6. 负载格式

### 6.1 设备信息（Call / Answer）

```json
{
  "deviceName": "Xiaomi-23127PN0CC",
  "abilities": ["topic:YHome/cmd/bedroomAC", "skill:infrared_send"],
  "latestSeq": 42
}
```

| 字段 | 类型 | 说明 |
|------|:---:|------|
| deviceName | string | 设备名称 |
| abilities | string[] | `topic:xxx` 订阅的主题，`skill:xxx` 设备技能 |
| latestSeq | number | 最新消息序号，用于对端初始化当前序号 |

### 6.2 Json 消息

负载为 UTF-8 JSON，格式由业务层定义，协议层不做约束。

### 6.3 Raw 消息

负载为任意二进制数据，由应用层自行定义格式。

## 7. 并发起序号

### 7.1 Heartbeat + Call → Answer 流程

```
Device A (新上线)                       Network                    Device B (已在网)
     │                                     │                            │
     │── Heartbeat (广播) ─────────────────►│── Heartbeat ──────────────►│
     │   Type=0x01                          │   Type=0x01                │
     │                                     │                            │
     │                                     │   B 本地无 A 记录 →         │
     │                                     │◄── Call (单播) ─────────────│
     │                                     │   Type=0x03                 │
     │   A 收到 Call, 从负载中               │   负载含 B 的设备信息       │
     │   记录 B 的设备信息                   │                            │
     │                                     │                            │
     │── Answer (单播) ────────────────────►│                            │
     │   Type=0x04                          │                            │
     │   负载含 A 的设备信息                  │   B 收到 Answer,            │
     │                                     │   记录 A 的设备信息          │
     │                                     │                            │
     │              ╔══ 双方互知 ══╗        │                            │
```

### 7.2 有序消息 + Ack 流程

```
Sender (当前序号=5)                          Receiver (当前序号=5)
     │── Json ─────────────────────────────►│
     │   Type=0x10 SeqNum=5                  │
     │   Flags=0x03 (AckRequired+Ordered)    │
     │                                       │  Ordered=1, SeqNum=5 == 当前序号 → 消费
     │   ⏱ 启动超时定时器                     │  当前序号 → 6
     │◄── Ack ──────────────────────────────│
     │   Type=0x05 AckSeq=5 CurrentSeq=6     │
     │                                       │
     │   收到 Ack, CurrentSeq=6 → 确认 ✓      │
     │   取消定时器                           │
     │                                       │
     │   下一条：SeqNum=6                     │

    —— 若超时未收到 Ack ——
    │   重传 (最多 5 次，间隔指数递增)        │
    │   150 → 300 → 600 → 1200 → 2400 ms     │
    │   仍失败 → 通知上层失败                │
```

### 7.3 乱序到达

```
Sender 连续发送 SeqNum=5, 6, 7
Flags=0x03 (AckRequired+Ordered)
网络导致 Receiver 收到 5, 7, 6

收到 SeqNum=5: 5==5 → 消费, 当前序号→6, 回复 Ack(5, 6)
收到 SeqNum=7: 7>6 → 丢弃, 回复 Ack(7, 6) ← 告知发送方当前序号仍为 6
收到 SeqNum=6: 收到重传的 6, 6==6 → 消费, 当前序号→7, 回复 Ack(6, 7)
                                        ↑ (此后 7 还没收到，等待重传)
收到 SeqNum=7: 收到重传的 7, 7==7 → 消费, 当前序号→8, 回复 Ack(7, 8)
```

## 8. 帧示例

### 心跳包（11 字节，无负载）
```
59 48 01 01 00 00 00 00 00 83 F0
│     │  │  │     │  │     └──────── CRC16
│     │  │  │     │  └────────── PayLen=0
│     │  │  │     └───────────── Flags=0x00
│     │  │  └─────────────────── SeqNum=0
│     │  └────────────────────── Type=Heartbeat
│     └───────────────────────── Version=0x01
└─────────────────────────────── Magic "YH"
```

### Call 包（设备信息 55 字节负载）
```
59 48 01 03 00 00 00 00 37 XX XX {...55 bytes JSON...}
                 │        │
                 └────────┴─ SeqNum=0, PayLen=55
```

### Json + AckRequired + Ordered 包
```
59 48 01 10 00 05 03 00 37 XX XX {...55 bytes JSON...}
                 │     │
                 │     └─ Flags=0x03 (AckRequired 0x01 | Ordered 0x02)
                 └─ SeqNum=5
```

### Ack 包（4 字节负载）
```
59 48 01 05 00 06 00 00 04 XX XX [00 05 00 06]
                 │                 │     │
                 └─ SeqNum=6       └─────┴─ Payload: AckSeq=5, CurrentSeq=6
```

## 9. 常量

| 常量 | 值 | 说明 |
|------|-----|------|
| `MAGIC` | `0x59 0x48` | 协议魔数 |
| `VERSION` | `0x01` | 协议版本 |
| `HEADER_SIZE` | `11` | 帧头字节数 |
| `ACK_PAYLOAD_SIZE` | `4` | Ack 负载字节数 |
| `PORT` | `8899` | 通信端口 |

| `OFFLINE_TIMEOUT` | `4500` ms | 离线超时 |
| `ACK_BASE_TIMEOUT` | `150` ms | 首次重传等待超时 |
| `ACK_MAX_RETRIES` | `5` | 最大重传次数 |
| `ACK_BACKOFF_MULTIPLIER` | `2` | 重传间隔倍增因子 |
| `BUFFER_SIZE` | `1024` | 接收缓冲区大小 |
