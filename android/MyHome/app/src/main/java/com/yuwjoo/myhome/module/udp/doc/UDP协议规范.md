# UDP 协议规范

## 1. 帧结构

```
┌──────────┬──────────┬────────────┬───────────┬──────────┬───────────┬──────────┐
│ Byte 0-1 │ Byte 2   │ Byte 3-4   │ Byte 5    │ Byte 6-7 │ Byte 8-9  │ Byte 10+ │
│  Magic   │   Type   │  SeqNum    │  Flags    │  PayLen  │  CRC16    │ Payload  │
│  2 bytes │  1 byte  │  2 bytes   │  1 byte   │  2 bytes │  2 bytes  │ N bytes  │
└──────────┴──────────┴────────────┴───────────┴──────────┴───────────┴──────────┘
                         ◄────────────── 定长帧头 10 字节 ─────────────────►
```

| 偏移 | 字节 | 字段 | 说明 |
|:---:|:---:|------|------|
| 0 | 2 | **Magic** | 协议魔数，固定 `0x59 0x48`（ASCII `YH`） |
| 2 | 1 | **Type** | 消息类型，见 [§2](#2-消息类型) |
| 3 | 2 | **SeqNum** | 消息序号（uint16 大端序），见 [§3](#3-消息序号-seqnum) |
| 5 | 1 | **Flags** | 标志位，见 [§4](#4-标志位) |
| 6 | 2 | **Payload Len** | 负载字节数（uint16 大端序），空负载为 `0x0000` |
| 8 | 2 | **CRC16** | 校验值（uint16 大端序），见 [§5](#5-crc16-校验) |
| 10 | N | **Payload** | 负载数据，UTF-8 JSON |

帧头固定 **10 字节**，完整帧长 = 10 + Payload Len。

## 2. 消息类型

| 分类 | Type | 名称 | 说明 |
|:---:|:---:|------|------|
| **系统** | `0x01` | Heartbeat | 设备在线宣告，周期性广播 |
| | `0x02` | Offline | 设备主动离网通知 |
| | `0x03` | Call | 向新发现设备发起呼叫，交换设备信息与序号，见 [§7.1](#71-heartbeat--call--answer-流程) |
| | `0x04` | Answer | 回应 Call，交换设备信息与序号，见 [§7.1](#71-heartbeat--call--answer-流程) |
| | `0x05` | Ack | 消息确认应答，见 [§3.3](#33-ack-消息格式) |
| | `0x06-0x0F` | 保留 | — |
| **业务** | `0x10` | Json | JSON 消息，见 [§6.2](#62-json-消息) |
| | `0x11` | Raw | 原始消息，负载为自定义二进制 |
| | `0x12-0xEF` | 保留 | — |
| | `0xF0-0xFF` | 保留 | — |

## 3. 消息序号 SeqNum

### 3.1 核心概念

每个客户端按 **内网主机号**（IP 最后一字节，0-255）维护一份序号映射表，记录从每个主机 **最新处理的有序消息序号**（初始值 = 0，表示尚未收到任何有序消息）。该记录仅随 Ordered=1 的消息更新，无序消息不影响序号记录。

### 3.2 序号初始化（Call / Answer 交换）

设备之间通过 Call 和 Answer 完成设备信息与序号的相互交换：

```
Call 负载中的 latestSeq = "我方已处理过的、来自你方的有序消息的最新序号"
Answer 同理
```

- 主机 2 收到主机 1 的心跳，本地无主机 1 记录 → 主机 2 向主机 1 单播 Call
  - 负载含主机 2 的设备信息和 `latestSeq` = 主机 2 记录的主机 1 的最新有序序号
- 主机 1 收到 Call → 保存主机 2 的设备信息 → 回复 Answer
  - 负载含主机 1 的设备信息和 `latestSeq` = 主机 1 记录的主机 2 的最新有序序号
- 主机 2 收到 Answer → 保存主机 1 的设备信息

**交换完成后，发送方以对方给的 `latestSeq + 1` 作为向该对端发送有序消息的起始序号**。例如 B 告诉 A `latestSeq=5`，则 A 发给 B 的第一条有序消息序号为 6。

### 3.3 有序消息规则

**发送**：
- 必须等待上一条有序消息**确认（Ack）** 后，才能发送下一条
- 每次发送序号 = 上一条序号 + 1
- 超时未收到 Ack 则重传（最多 5 次，指数退避）

**接收**：
- 只接受序号 = **本地记录的最新序号 + 1** 的消息
- 序号不匹配（重复的、超前的、错误的）一律**丢弃**
- 消费后更新本地记录的最新序号
- Ordered=1 隐含需要 Ack，消费后**必须**回复 Ack

**Ack 后同步**：发送方收到 Ack 后即可发送下一条有序消息。

### 3.4 无序消息规则

- 无序消息 **立即发送**，不等待上一条消息完成
- **支持并行**：多条无序消息可同时发送，无需排队
- 接收端收到即处理，不做序号校验，不回复 Ack
- 无序消息不保证送达、不保证顺序、可能重复

### 3.5 Ack 消息格式

Ack 的 Payload 为 4 字节定长二进制：

```
┌──────────────┬──────────────┐
│  Byte 0-1    │  Byte 2-3    │
│  AckSeq      │  CurrentSeq  │
│  uint16      │  uint16      │
└──────────────┴──────────────┘
```

| 字段 | 字节 | 说明 |
|------|:---:|------|
| **AckSeq** | 0-1 | 被确认的消息序号（收到的 SeqNum） |
| **CurrentSeq** | 2-3 | 接收方处理本消息后最新记录的有序序号 |

> 发送方通过 CurrentSeq 确认对端消费进度。

### 3.6 使用场景对照

| 消息 | 发送方式 | Ordered | 说明 |
|------|:---:|:---:|------|
| Heartbeat | 广播 | 0 | 无序，收到即处理 |
| Offline | 广播 | 0 | 无序，收到即处理 |
| Call | 单播 | 0 | 无序，携带 latestSeq 初始化序号，等待 Answer |
| Answer | 单播 | 0 | 无序，携带 latestSeq 初始化序号，收到即记录 |
| Ack | 单播 | 0 | 无序，收到即处理 |
| Json | 单播 | 按需 | 有序时逐条等待确认；无序时并行发送 |
| Raw | 单播 | 按需 | 有序时逐条等待确认；无序时并行发送 |

## 4. 标志位

| Bit | 名称 | 说明 |
|:---:|------|------|
| 0 | **Ordered** | `0` 无序送达（立即发送，并行处理，不保证送达，可能重复/丢包）；`1` 有序送达（逐条发送，等待确认，不重复、不丢包） |
| 1-7 | 保留 | 必须为 0 |

> **Ordered=1 隐含需要 Ack**：接收端消费有序消息后必须回复 Ack，发送端等 Ack 后才发下一条。无需单独的 AckRequired 标志。

## 5. CRC16 校验

- **算法**：CRC-16/CCITT-FALSE
- **多项式**：`0x1021`
- **初始值**：`0xFFFF`
- **校验范围**：帧头第 0~5 字节（Magic ~ Payload Len）+ 全部 Payload 字节

```
CRC16( Magic[2] + Type[1] + SeqNum[2] + Flags[1] + PayLen[2] + Payload[N] )
```

处理流程：

```
发送方：计算 CRC16 → 填入 → 发送
接收方：提取 CRC16 → 对相同范围重算 → 比对
        一致 → 继续处理
        不一致 → 丢弃
```

## 6. 负载格式

### 6.1 设备信息（Call / Answer）

```json
{
  "deviceName": "Xiaomi-23127PN0CC",
  "abilities": ["topic:YHome/cmd/bedroomAC", "skill:infrared_send"],
  "latestSeq": 42,
  "heartbeatInterval": 1500,
  "heartbeatTimeout": 4500
}
```

| 字段 | 类型 | 说明 |
|------|:---:|------|
| deviceName | string | 设备名称 |
| abilities | string[] | `topic:xxx` 订阅的主题，`skill:xxx` 设备技能 |
| latestSeq | number | 我方已处理的来自你方的有序消息的最新序号，用于对端确定发送起始序号（见 [§3.2](#32-序号初始化call--answer-交换)） |
| heartbeatInterval | number | 心跳间隔（ms），`0` 表示不发送心跳 |
| heartbeatTimeout | number | 心跳过期间隔（ms），超时未收到心跳判定离线 |

### 6.2 Json 消息

负载为 UTF-8 JSON，格式由业务层定义，协议层不做约束。

### 6.3 Raw 消息

负载为任意二进制数据，由应用层自行定义格式。

### 7.1 Heartbeat + Call → Answer 流程

```
Device A (新上线)                       Network                    Device B (已在网)
     │                                     │                            │
     │── Heartbeat (广播) ─────────────────►│── Heartbeat ──────────────►│
     │   Type=0x01 Flags=0x00               │   Type=0x01                │
     │                                     │                            │
     │                                     │   B 本地无 A 记录 →         │
     │                                     │◄── Call (单播) ─────────────│
     │                                     │   Type=0x03                 │
     │   A 收到 Call：                      │   Payload:                 │
     │   · 保存 B 的设备信息                 │   { deviceName, abilities, │
     │   · 记录 B 给的最新序号               │     latestSeq: 0,          │
     │     （之后 A→B 的有序消息             │     heartbeatInterval,     │
     │      从 0+1=1 开始）                 │     heartbeatTimeout }      │
     │                                     │                            │
     │── Answer (单播) ────────────────────►│                            │
     │   Type=0x04                          │                            │
     │   Payload:                           │   B 收到 Answer：           │
     │   { deviceName, abilities,           │   · 保存 A 的设备信息        │
     │     latestSeq: 0,                    │   · 记录 A 给的最新序号      │
     │     heartbeatInterval,               │     （之后 B→A 的有序消息    │
     │     heartbeatTimeout }               │      从 0+1=1 开始）        │
     │                                     │                            │
     │              ╔══ 双方互知，序号已同步 ══╗                         │
```

### 7.2 有序消息 + Ack 流程

```
A (向B发送)                           B (记录A的最新序号=5)
     │── Json Ordered ─────────────────────►│
     │   Type=0x10 SeqNum=6                  │  检查: 6 == 5+1? ✓
     │   Flags=0x01                          │  消费 → 记录A→6
     │                                       │
     │   ⏱ 启动超时定时器                     │◄── Ack(6, 6) ───────────────│
     │◄── Ack ──────────────────────────────│
     │   收到 Ack → 确认 ✓, 取消定时器        │
     │                                       │
     │   下一条：SeqNum=7                     │
     │── Json Ordered ─────────────────────►│
     │   SeqNum=7                            │  检查: 7 == 6+1? ✓
     │                                       │  消费 → 记录A→7
     │                                       │◄── Ack(7, 7) ───────────────│
     │◄── Ack ──────────────────────────────│
     │   ✓                                  │

    —— 若超时未收到 Ack ——
     │   重传 (最多 5 次，间隔指数递增)        │
     │   150 → 300 → 600 → 1200 → 2400 ms     │
     │   仍失败 → 通知上层失败                │
```

### 7.3 有序消息重复到达

```
A 向 B 发送有序消息
A ── Json SeqNum=6 ──► B  消费 (记录B→6)  Ack(6,6) 返回，但 Ack 丢包
A 超时，重传 SeqNum=6 ──► B  检查: 6 != 6+1 → 丢弃
                           B ◄── Ack(6, 6) (告知我已到 6)
A 收到 Ack → 确认 ✓，继续发送 SeqNum=7
```

### 7.4 无序消息并行发送

```
A 同时向 B 发送多条无序消息：
     │── Json Unordered Seq=0 ─────────────►│ 收到即处理（无序号校验）
     │── Raw  Unordered Seq=0 ─────────────►│ 收到即处理
     │── Json Unordered Seq=0 ─────────────►│ 收到即处理
     │                                       │
     │   (三条消息并行发送，互不等待)           │  (三条消息可能以任意顺序到达)
```

59 48 01 00 00 00 00 00 XX XX
│     │  │        │  └─────── PayLen=0

```
59 48 03 00 00 00 00 37 XX XX {...55 bytes JSON...}
        │              │
        └──────────────┴─ Flags=0x00 (无序), PayLen=55
```

### Json + Ordered 包
```
59 48 10 00 06 01 00 37 XX XX {...55 bytes JSON...}
                 │
                 └─ Flags=0x01 (Ordered)
```

### Ack 包（4 字节负载）
```
59 48 05 00 06 00 00 04 XX XX [00 06 00 06]
                          │     │        │
                          └─────┴────────┴─ Payload: AckSeq=6, CurrentSeq=6
```
