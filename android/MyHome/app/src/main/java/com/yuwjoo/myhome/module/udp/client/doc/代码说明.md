# UdpClient 模块代码说明

## 模块目录

```
client/
├── UdpClient.kt            # 统一入口，组合子模块，暴露 connect/disconnect/send/监听 API
├── NetworkMonitor.kt       # 网络监听：WiFi 状态变化 → 带防抖的断线重连
├── FrameCodec.kt           # 帧编解码：10 字节帧头 + Payload + CRC16 校验
├── ClientConfig.kt         # 配置聚合：协议常量、帧类型/标志位、心跳/Ack 参数
├── HeartbeatEngine.kt      # 心跳引擎：定时广播心跳 + 内部离线检测
├── DeviceRegistry.kt       # 设备注册表：CRUD、在线状态、各设备独立超时参数
├── MessageRouter.kt        # 消息路由：按帧类型分发、有序消息序号校验与 Ack 回复
├── AckEngine.kt            # Ack 引擎：按主机串行发送、无限重试直到 ACK 或设备离线
├── SeqManager.kt           # 序号管理：按主机号维护收发序号、uint16 回绕、严格递增校验
├── RetryPolicy.kt          # 退避策略：初始超时、指数退避、最大超时封顶
└── socket/
    ├── UdpSocket.kt        # UDP Socket 管理：创建/销毁、三种发送、本机 IP 收集
    └── SocketReader.kt     # 帧读取器：协程循环接收、自收过滤、解码输出
```

---

## 模块解读

### UdpClient.kt

> 统一入口，组合全部子模块，对外暴露简洁的 `connect` / `disconnect` / `send` / 监听 API。

| 成员/方法 | 类型 | 说明 |
|-----------|------|------|
| `isConnected` | `Boolean` | 当前是否已连接 |
| `onConnectionChanged` | 回调 | 连接状态变化时通知上层 |
| `onDeviceChanged` | 回调 | 设备列表变化时通知上层 |
| `onMessageReceived` | 回调 | 收到业务消息（JSON/Raw）时通知上层 |
| `devices` | 属性 | 返回全部已知设备列表 |
| `onlineDevices` | 属性 | 返回当前在线设备列表 |
| `connect(context)` | 方法 | 启动网络监听，WiFi 可用时自动完成连接 |
| `disconnect(context)` | 方法 | 广播 OFFLINE → 停止所有子模块 → 清理资源 |
| `send(type, payload, targetIp, ordered)` | 方法 | 发送帧：`targetIp=null` 广播，否则单播；`ordered` 控制是否可靠送达 |
| `doConnect()` | 私有方法 | 创建 Socket（自动启动帧读取）→ 注册回调链 → 启动心跳 |
| `doDisconnect()` | 私有方法 | 广播 OFFLINE → 停止心跳/Ack → 销毁 Socket（自动停止帧读取）→ 清空状态 |

### UdpSocket.kt

> 管理 `MulticastSocket` 完整生命周期，持有 `SocketReader` 负责协程循环接收解码，通过 `onFrameReceived` 回调向外输出帧数据。`create()` 自动启动帧读取，`destroy()` 自动停止。

| 成员/方法 | 类型 | 说明 |
|-----------|------|------|
| `isOpen` | `Boolean` | Socket 是否已创建且未关闭 |
| `isReading` | `Boolean` | 帧读取器是否正在运行 |
| `onFrameReceived` | 回调 | 解码成功后回调，传递 `FrameData` 和来源 IP |
| `create()` | 方法 | 创建 Socket 绑定端口 8899 → 加入组播组 → 收集本机 IP → 启动帧读取 |
| `destroy()` | 方法 | 停止帧读取 → 离开组播组 → 关闭 Socket |
| `receive(buffer)` | 方法 | 阻塞式接收一个 UDP 报文，返回 `DatagramPacket` 或 null |
| `sendUnicast(data, targetIp)` | 方法 | 单播发送到指定 IP 的 8899 端口 |
| `sendMulticast(data)` | 方法 | 组播发送到 239.0.0.100:8899 |
| `sendBroadcast(data)` | 方法 | 广播发送到 255.255.255.255:8899 |
| `isLocalAddress(ip)` | 方法 | 判断指定 IP 是否为本机地址 |

---

### SocketReader.kt

> 独立协程循环接收 UDP 报文，调用 `UdpSocket.receive()` 获取原始报文，完成自收过滤（`isLocalAddress`）和解码（`FrameCodec.decode`），通过 `onFrameReceived` 回调输出 `FrameData`。

| 成员/方法 | 类型 | 说明 |
|-----------|------|------|
| `isRunning` | `Boolean` | 是否正在运行 |
| `onFrameReceived` | 回调 | 解码成功后回调，传递 `FrameData` 和来源 IP |
| `start()` | 方法 | 启动协程，循环调用 `udpSocket.receive()` 接收解码 |
| `stop()` | 方法 | 取消协程，停止接收 |

---

### NetworkMonitor.kt

> 监听 WiFi 连接状态，状态变化时带防抖回调，驱动 `UdpClient` 的自动重连。

| 成员/方法 | 类型 | 说明 |
|-----------|------|------|
| `start(context)` | 方法 | 注册 `NetworkCallback`，仅关注 WiFi 传输类型；启动时立即回调当前状态 |
| `stop(context)` | 方法 | 取消防抖 → 注销 `NetworkCallback` |
| `debounceNotify(available)` | 私有方法 | 1.5s 防抖：期间无新变化才真正回调，避免 WiFi 短暂抖动导致频繁连断 |

---

### FrameCodec.kt

> 帧的编码与解码，内含 CRC16-CCITT 校验。

| 成员/方法 | 类型 | 说明 |
|-----------|------|------|
| `encode(type, seqNum, flags, payload)` | 方法 | 构建 10 字节帧头（Magic/Type/SeqNum/Flags/PayLen/CRC）+ Payload，返回完整帧字节数组 |
| `decode(data)` | 方法 | 校验魔数 → 校验 CRC → 解析各字段 → 返回 `FrameData`，任一失败返回 null |
| `crc16(data)` | 方法 | 计算 CRC16-CCITT 校验值 |

---

### ClientConfig.kt

> 协议常量和配置聚合，所有模块共享。

| 成员/方法 | 类型 | 说明 |
|-----------|------|------|
| `MAGIC` | `0x5948` | 协议魔数，帧头前两字节 |
| `HEADER_SIZE` | `10` | 帧头固定字节数 |
| `PORT` | `8899` | UDP 通信端口 |
| `MULTICAST_ADDR` | `239.0.0.100` | 组播地址 |
| `BROADCAST_ADDR` | `255.255.255.255` | 广播地址 |
| `BUFFER_SIZE` | `1024` | 接收缓冲区大小 |
| `Type.*` | 常量组 | 帧类型：HEARTBEAT / OFFLINE / CALL / ANSWER / ACK / JSON / RAW |
| `Flags.*` | 常量组 | 标志位：NONE / ORDERED |
| `HEARTBEAT_INTERVAL_MS` | `1500` | 本机心跳发送间隔（ms） |
| `HEARTBEAT_TIMEOUT_MS` | `4500` | 本机心跳过期间隔（ms），离线检测回退值 |
| `DEVICE_NAME` | 动态值 | 本机设备名，格式 `厂商-型号` |
| `hostId(ip)` | 方法 | 取 IP 最后一字节作为主机号（0-255） |

### HeartbeatEngine.kt

> 协程定时循环：自行编码并广播心跳帧，自行维护心跳时间表和离线检测。

| 成员/方法 | 类型 | 说明 |
|-----------|------|------|
| `recordHeartbeat(ip)` | 方法 | 记录收到某设备的心跳时间 |
| `start()` | 方法 | 启动协程，每 `HEARTBEAT_INTERVAL_MS` 执行：广播心跳 → 检测离线 |
| `stop()` | 方法 | 取消协程，清空心跳时间表 |
| `sendHeartbeat()` | 私有方法 | 编码 HEARTBEAT 帧（空负载）并广播 |
| `detectOffline()` | 私有方法 | 遍历在线设备，对比心跳时间与超时阈值，超时则调用 `DeviceRegistry.markOffline` |

---

### DeviceRegistry.kt

> 线程安全的设备注册表，管理 LAN 中所有设备的在线状态和心跳参数。

| 成员/方法 | 类型 | 说明 |
|-----------|------|------|
| `onDeviceChanged` | 回调 | 设备增删或状态变化时通知 |
| `onDeviceOffline` | 回调 | 设备离线时通知，用于 AckEngine 中止重试 |
| `register(ip, name, abilities, ...)` | 方法 | 注册或更新设备信息，自动标记在线 |
| `markOnline(ip)` | 方法 | 从离线恢复在线时调用，重置 `offlineAt` |
| `markOffline(ip)` | 方法 | 标记离线，记录 `offlineAt` 时间戳，触发回调 |
| `get(ip)` | 方法 | 按 IP 查询单个设备 |
| `getAll()` | 方法 | 返回全部已知设备 |
| `getOnline()` | 方法 | 返回当前在线设备 |
| `clear()` | 方法 | 清空所有记录 |

**`LanDevice` 数据类**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `ip` | `String` | 设备 IP |
| `deviceName` | `String` | 设备名称 |
| `abilities` | `List<String>` | 能力列表，`topic:` 开头表示订阅主题，`skill:` 开头表示设备技能 |
| `online` | `Boolean` | 是否在线 |
| `offlineAt` | `Long` | 离线时间戳，`0` 表示当前在线 |
| `heartbeatInterval` | `Long` | 该设备宣告的心跳间隔（ms） |
| `heartbeatTimeout` | `Long` | 该设备宣告的心跳过期间隔（ms） |

### MessageRouter.kt

> 按帧类型分发到不同处理逻辑，是接收侧的中枢。

| 成员/方法 | 类型 | 说明 |
|-----------|------|------|
| `onMessageListener` | 回调 | 有序消息校验通过后、或无序消息直接投递上层 |
| `dispatch(frame, fromIp)` | 方法 | 按 `frame.type` 分发到对应 handler |
| `handleHeartbeat(frame, fromIp)` | 私有方法 | 设备未知/离线 → 发起 CALL；已知在线 → 记录心跳到 HeartbeatEngine + 刷新在线状态 |
| `handleOffline(frame, fromIp)` | 私有方法 | 标记设备离线 |
| `handleCall(frame, fromIp)` | 私有方法 | 注册对方设备 → 初始化发送序号 → 回复 ANSWER |
| `handleAnswer(frame, fromIp)` | 私有方法 | 注册对方设备 → 初始化发送序号 |
| `handleAck(frame, fromIp)` | 私有方法 | 解析 Ack 序号 → 通知 `AckEngine` 消息已送达 |
| `handleOrderedMessage(frame, fromIp)` | 私有方法 | 三路序号校验：接受投递 / 重复回 Ack / 乱序无视 |

### AckEngine.kt

> 按主机串行发送有序消息，前一条 ACK 后才发下一条，无限重试直到成功或设备离线。

| 成员/方法 | 类型 | 说明 |
|-----------|------|------|
| `enqueue(hostId, targetIp, buildFrame, onSuccess, onFailure)` | 方法 | 消息入队，由对应主机的串行协程处理 |
| `onAck(hostId, seqNum)` | 方法 | 收到 ACK，通知对应发送协程继续下一条 |
| `abort(hostId)` | 方法 | 设备离线：取消协程 → 回退序号 → 通知所有待发消息失败 |
| `stop()` | 方法 | 停止所有主机的发送协程 |

**内部类 `HostSender`**：

| 成员/方法 | 说明 |
|-----------|------|
| `enqueue(task)` | 将 `SendTask` 加入该主机的无界队列 |
| `onAck(seqNum)` | 标记已确认序号，唤醒等待中的协程 |
| `abort()` | 取消协程、回退序号、回调队列中所有任务的 `onFailure` |
| `run()` | 串行消费：取任务 → `SeqManager.nextSendSeq` 分配序号 → 发送 → 循环等待 ACK（超时重发，退避递增）→ 成功后处理下一条 |

---

### SeqManager.kt

> 按主机号维护收发有序序号，uint16 回绕安全。

| 成员/方法 | 类型 | 说明 |
|-----------|------|------|
| `getRecvSeq(hostId)` | 方法 | 返回已从该主机接收的最大有序序号 |
| `initSendSeq(hostId, latestSeq)` | 方法 | CALL/ANSWER 握手时用对方提供的序号初始化发送基线 |
| `nextSendSeq(hostId)` | 方法 | 递增当前发送序号并返回（uint16 回绕） |
| `rollbackSendSeq(hostId)` | 方法 | Abort 时回退序号，使下次分配复用 |
| `tryConsume(hostId, seq)` | 方法 | 校验序号：等于期望值 → ACCEPTED；小于 → DISCARD_BUT_ACK；大于 → DISCARD_NO_ACK |
| `reset()` | 方法 | 清空全部主机的收发序号 |

---

### RetryPolicy.kt

> 指数退避超时计算，上限封顶后不再增长。

| 成员/方法 | 类型 | 说明 |
|-----------|------|------|
| `baseTimeoutMs` | `150` | 初始超时（ms） |
| `backoffMultiplier` | `2` | 退避倍数 |
| `maxTimeoutMs` | `5000` | 最大超时上限（ms） |
| `timeoutFor(retryIndex)` | 方法 | `150 × 2^retryIndex`，达到 5s 后封顶 |
