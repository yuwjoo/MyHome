# UdpClient 模块设计

## 模块划分

```
client/
├── UdpClient.kt            # 统一入口，组合子模块，暴露 connect/disconnect/send/监听 API
├── FrameCodec.kt           # 帧编解码：encode（10 字节帧头+Payload+CRC）、decode（校验+解析）
├── MessageRouter.kt        # 消息路由：按 Type 分发 → 有序序号校验/Ack 回复
├── HeartbeatEngine.kt      # 心跳引擎：定时广播 Heartbeat + 内部离线检测
├── AckEngine.kt            # Ack 引擎：有序消息注册 → 指数退避重传 → 超时回调
├── RetryPolicy.kt          # 重试策略：首超时间、最大次数、退避倍数
├── DeviceRegistry.kt       # 设备注册表：CRUD、在线状态、心跳参数
├── SeqManager.kt           # 序号管理：按主机号维护对端有序序号，严格递增校验
├── NetworkMonitor.kt       # 网络监听：WiFi 状态变化 → 断线重连
├── ClientConfig.kt         # 配置聚合：协议常量、心跳/Ack/重试参数
└── socket/
    ├── UdpSocket.kt        # UDP Socket 管理：创建/销毁、三种发送、本机 IP 收集
    └── SocketReader.kt     # 帧读取器：协程循环接收、自收过滤、解码输出
```

## 发现阶段

设备从接入局域网到互相感知设备信息的完整流程。

> **说明**：心跳采用 UDP 广播，本机不接收自己发出的心跳包。

```mermaid
flowchart TD
    subgraph 本机周期任务
        A[设备接入局域网] --> B[启动 UDP 广播监听]
        B --> C[启动心跳定时器]
        C --> D[每隔固定间隔]
        D --> E[广播心跳包]
        E --> F{WiFi 是否仍连接}
        F -->|是| D
        F -->|否| G[停止广播，进入等候重连]
    end
```

```mermaid
flowchart TD
    A[收到心跳帧] --> B{设备是否已知且在线}

    B -->|否：未知或曾离线| C[向该设备单播发起 CALL]
    C --> D[CALL 携带：本机设备名和能力、本机记录的对方序号]
    D --> E{对方处理 CALL}
    E --> F[对方记录本机设备信息]
    F --> G[对方以本机提供的序号初始化发送表]
    G --> H[对方单播回复 ANSWER]
    H --> I[ANSWER 携带：对方设备名和能力、对方记录的本机序号]
    I --> J{本机处理 ANSWER}
    J --> K[本机记录对方设备信息]
    K --> L[本机以对方提供的序号初始化发送表]
    L --> M[双方互相感知、序号同步完毕]

    B -->|是：已知在线| N[刷新该设备最后活跃时间]
    N --> O[设备保持在线]

    P[收到 OFFLINE 帧] --> Q[立即标记该设备离线]
    Q --> R[通知上层、终止该设备的 ACK 重试]

    S[定时器周期触发] --> T[遍历所有在线设备]
    T --> U{当前时间 - 最后活跃时间<br/>超过该设备声明的超时阈值?}
    U -->|否| S
    U -->|是| V[标记离线]
    V --> W[通知上层、终止该设备的 ACK 重试]
```

## 通信阶段

设备间发送和接收消息的完整流程，包含有序消息的序号校验、ACK 确认、指数退避重传机制。

### 发送流程

同一目标设备的有序消息**串行发送**，前一条确认后才发下一条；无序消息直接发送不等待。

```mermaid
flowchart TD
    A[上层发起消息发送] --> B{是否指定目标设备}

    B -->|广播| C[帧序号置零、不标记有序]
    C --> D[UDP 广播发送]
    D --> E[完成，无确认]

    B -->|单播| F{是否要求可靠送达}

    F -->|否：无序| G[帧序号置零、不标记有序]
    G --> H[UDP 单播发送]
    H --> E

    F -->|是：有序| I[加入该目标设备的串行发送队列]
    I --> J[等待该设备前序消息确认完毕]
    J --> K[分配递增序号、构建带序号帧]
    K --> L[UDP 单播发送]
    L --> M[等待对方 ACK]

    M --> N{在超时时间内收到 ACK?}
    N -->|是| O[通知成功，处理队列下一条]
    N -->|否| P[等待退避间隔后重发同一帧]
    P --> Q{退避超时已达上限?}
    Q -->|否| N
    Q -->|是| P

    R[目标设备被标记离线] --> S[清空该设备发送队列]
    S --> T[通知队列中所有消息发送失败]
```

`Q -->|是| P` 表示退避超时达到上限后不再增长，以固定最大间隔持续重试，直到 ACK 或设备离线，不会主动放弃。

### 接收流程

```mermaid
flowchart TD
    A[UDP 收到数据包] --> B{来源是否为本机}
    B -->|是| C[丢弃，不处理自收包]
    B -->|否| D{帧校验：魔数匹配 + CRC 正确}
    D -->|失败| E[丢弃该帧]
    D -->|通过| F{帧类型}

    F -->|HEARTBEAT| G[进入发现/保活流程<br/>见发现阶段流程图]
    F -->|OFFLINE| H[标记设备离线]
    H --> I[通知上层 + 终止该设备 ACK 重试]

    F -->|CALL| J[记录对方设备信息、同步序号]
    J --> K[回复 ANSWER<br/>携带本机信息和记录的对方序号]

    F -->|ANSWER| L[记录对方设备信息、同步序号]
    L --> M[双方序号同步完成]

    F -->|ACK| N[解析被确认的序号]
    N --> O[通知对应发送协程：该消息已送达]

    F -->|业务帧 JSON/RAW| P{是否标记为有序}
    P -->|无序| Q[直接投递上层]
    Q --> R[不回复 ACK]

    P -->|有序| S{序号校验}
    S -->|等于期望值<br/>期望值 = 本地记录 + 1| T[投递上层]
    T --> U[更新本地接收序号]
    U --> V[回复 ACK<br/>含确认序号和本地最新序号]

    S -->|小于期望值：重复消息| W[丢弃]
    W --> V

    S -->|大于期望值：乱序| X[丢弃，不回复 ACK]
    X --> Y[发送方超时后会重传<br/>届时序号可能已变为期望值]
```

### 重试策略

有序消息无需限制重试次数，仅通过最大超时时间防止退避无限增长；重试将持续到 ACK 或设备离线为止。

| 参数 | 含义 |
|------|------|
| 初始超时 | 首次发送后等待 ACK 的时间 |
| 退避倍数 | 每次超时后等待时间乘以此倍数 |
| 最大超时 | 退避增长的上限，达到后不再增加 |

**示例**（初始 150ms / 倍数 ×2 / 最大 5s）：

| 轮次 | 等待超时 |
|------|---------|
| 第 1 次发送 | 150ms |
| 第 2 次（重试） | 300ms |
| 第 3 次（重试） | 600ms |
| 第 4 次（重试） | 1.2s |
| 第 5 次（重试） | 2.4s |
| 第 6 次及以后 | 5s（封顶） |

> 无限重试，直至收到 ACK 或设备离线。
